# Roadmap

## Phase 1 — Foundation (implemented in this MVP)

Structured schemas, synthetic demonstration, project and analysis planning surfaces, Claim Ledger, an extensible 18-card Method Library, researcher-created local Method Cards, provenance timeline, privacy boundary, deterministic evidence profile, audit export, Docker Compose, and FastAPI service foundation.

## Phase 2 — Controlled local execution

Containerized job protocol, immutable run snapshots, hash-addressed artifacts, strict dataset alignment, and a synthetic end-to-end RNA-seq association fixture using `filterByExpr`, TMM, limma-voom, eBayes, and BH FDR.

## Phase 3 — Scientific depth

cameraPR gene-set testing, explicit FDR families, safe K-fold and repeated K-fold validation, leakage detection, sensitivity orchestration, richer Method Cards, and reproducibility bundles.

## Phase 4 — AI reasoning

Provider-neutral adapters, schema-validated proposals, researcher approval lifecycle, Context Inspector previews, mock-to-live integration, adversarial reviewer records, and conservative wording assistance.

## Phase 5 — Production hardening

PostgreSQL, institutional authentication, role-based approval, signed provenance, isolated compute workers, malware-aware uploads, retention controls, method curation governance, observability with scientific-data redaction, and external security review.

## Major risks

- A polished interface could make incomplete evidence feel stronger than it is.
- Sanitized summaries can still leak sensitive information if policy lacks context.
- Method Cards can become stale without ownership and version review.
- Reproducibility metadata may expose sensitive paths unless sanitized.
- Cross-validation helpers can leak information through preprocessing outside folds.
- AI explanations can exceed structured evidence unless rule warnings remain prominent.
